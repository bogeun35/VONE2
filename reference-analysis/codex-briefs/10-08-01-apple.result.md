what it is: Target 역할은 별도 조준점을 움직이고 사과를 쏘며, Basket 역할은 별도 바구니 센서로 날아오는 사과를 받는다. 컨트롤러는 비활성 사과를 무작위로 활성화하고 목표 수량을 채우면 열쇠를 활성화한다. 이번 결과는 근거가 확정된 파라미터 해독·타이머·선택·득점 이벤트 커널까지의 부분 구현이며, 실제 장치 물리와 렌더링은 완성되지 않았다.
stage compiles alone: 아니오. st_w_08_01, st_w_08_03 모두 2..8인 compile이 구체적 미구현 사유를 포함해 throw한다. supportedTypes는 요청된 대상 목록이며 플레이 가능 지원 목록으로 등록하면 안 된다. 등록·배포·커밋·푸시는 하지 않았다.

key findings:
- TargetPlayer 생성 경로는 ActorFactory.createTargetPlayer 0x1816a47f0 → PlayerTargetComponent.Creator 0x1816a48e3이고, BasketPlayer는 createBasketPlayer 0x1816a4910 → PlayerBasketComponent.Creator 0x1816a4980이다.
- 역할은 생성된 플레이어의 액터 순번으로 scene PlayerIndexList를 조회하여 배정한다(0x1816a4000, 0x1816a4048). InitPlayerIndexList는 조건부로 seeded RNG를 사용한 오름차순 Fisher-Yates 셔플을 한다(0x1816a64d4..0x1816a655d). 두 스테이지 모두 shufflePlayer=1을 저장한다. 해당 stage 호출부까지는 추적하지 않았으므로 실제 연결 검증은 미완료다. 역할 생성자가 독자적으로 추첨하는 코드는 없다.
- 컨트롤러 슬롯8은 FP64가 아니라 7개 int32/28 UTF-16 문자다(0x180970977, 0x1809709fc..0x180970cdf). 2~8인 목표는 8-1 [12,14,21,21,23,24,26], 8-3 [12,14,20,22,25,27,30]으로 실제 자료와 대조했다.
- 초기 생성 대기와 이 스테이지의 조준 발사 간격은 raw65536이다(0x1816abe90, Target 슬롯12, 0x1816d7172). 60Hz raw1092로 60틱 후16이 남고 61틱에 만료된다. 0.5~1.5초 다음 생성 간격은 사과 활성화의 RNG 소비가 끝난 뒤 뽑아야 한다(0x1816ac301, 0x1816ac327).
- 목표 달성 시 event1을 Key 타입17에, event47을 별도 Target 타입134에 보낸다(0x1816ac793..0x1816ac7c7). TargetPlayer 타입132와 Target 타입134를 혼동하면 안 된다.
- Apple 사과 센서는 24×24/오프셋(-12,-12), 바구니는 26×44/오프셋(-22,-30)이다(0x1816ab2c6..0x1816ab353, 0x181890ed8..0x181890f11). 바구니 실제 위치는 소유자의 귀 길이·스케일·Y반전에 의존한다(0x1818908a0).
- .cctor resolver를 실행해 사과 흔들기 효과 raw4915("0.075"), 폭발 효과 raw13107, 속도400, 반경250을 확인했다. 상수가 읽히지 않는다고 처리하지 않았다. 아직 물리 구현에는 쓰지 않는다.

unresolved:
- Apple 흔들림의 사인 함수는 런타임 조회표를 읽는다(0x1816465d0, 0x18164664b). 조회표와 점프·정규화·접촉 순서를 정확히 복원하지 못했다. Math.sin이나 일반 포물선으로 대체하지 않았다.
- Target 조준점 이동/카메라 제한/귀환/플레이어 깨우기, Basket 소유자 센서 변환은 분석했으나 구현하지 않았다. source-stage-runtime의 플레이어·카메라·입력·충돌 연결도 필요하다.
- Apple 활성화 RNG 소비, 12단계 상태 머신, 날아오는 사과 포획, 폭탄·사과 연쇄폭발, 효과음·애니메이션·카운터 표시는 미구현이다. ControllerUpdate는 활성화 요청만 반환하는 분석 커널이며 완전한 장치 update가 아니다.
- actor-runtime.js의 playerSpawns는 일반 Player만 선택한다. 역할 스폰은 원작의 scene 순번과 셔플을 보존하도록 별도로 연결해야 한다.
- 실제 스테이지 플레이 및 원작 일치 검수는 하지 않았다. 테스트 통과는 해독·부분 커널·명시적 컴파일 거부 검증을 의미한다.
- 초안의 rngRange가 multiply-high 방식이었던 오류는 landmine 및 0x181662090 대조 후 rejection+modulo로 수정했다. 중간 RNG 상태 테스트의 전사 오류도 독립 Python 정수 계산으로 바로잡았다.
