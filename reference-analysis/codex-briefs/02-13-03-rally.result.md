stage compiles alone: 아니오. 실제 st_w_13_03 2..8인 모두 compile()이 구체적인 물리 미해결 오류를 던진다. 분석용 inspectActors()만 일곱 배치를 해석하며, 해당 snapshot은 beforeStep/afterStep/solids에서도 실행을 거부한다. 등록하지 말 것.

key findings:
- ParseParameter 0x1816dfe40..0x1816e0276의 12슬롯을 확정했다. 모든 인원에서 최대16회/가속주기5회. 슬롯4/5가 0이어도 가속0을 뜻하지 않고 Initialize 기본 raw6553을 유지한다(0x1816dfce2 / 0x1816dfd43).
- OnUpdate 0x180476130은 빈 ret다. Post 상태 기계 0x1816e03f0은 초기 raw32768 대기(31 카운트다운 틱), 재생성 raw16384 대기(16틱)를 사용하며 진입 틱은 별도다.
- event9는 phase0/1에서도 받아들인다(0x1816e0ba2). 16번째 히트에서는 가속하지 않고 phase3만 설정하며, 다음 Post에 clearProc를 한 번 호출한다(0x1816e0bc4 / 0x1816e047d).
- 소실 event7은 ball reference만 지운 뒤 미완료일 때 카운트·패들 가속을 초기화한다. phase 변경은 다음 Post의 별도 작업이다(0x1816e0cf2..0x1816e0d6a / 0x1816e0494).
- 패들 반지름25 원/layer3(0x1816e6263 / 0x1816e517d), 레일 제한 (length/2)^2(0x1816e5237), 범위 밖 이동 전체 거부(0x1816e5fe5). 직사각형 solid나 끝점 clamp로 대체하면 다르다.
- 공은 stage 액터 목록이 아니라 controller createBall에서 동적 생성한다(0x1816e091d → RallyBallComponent.Creator 0x1816dda50). 패들 무작위 선택 및 -20..20도 FP RNG 교란이 있다(0x1816e06fe / 0x1816e085f).
